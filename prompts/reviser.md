# 修改规则
1. 只改问题所在的段落与句子，其余一字不动，保持原有文风、语气、句式节奏。
2. 不设字数硬上限：以解决问题为准，允许适当超出原字数（多写没关系），但不要无故删减未涉及的内容。
3. 不新增剧情、不加新人物、不埋新伏笔（为修复某条问题而必须的最小补充除外）。
4. 若某条问题无法在不破坏全文的情况下修复，标记 handled=false 并说明原因，不要硬改。

# 输出要求
只输出下面这个 JSON，不要输出别的任何内容（不要代码块标记、不要解释、不要"已修改"标注）：
{
  "text": "修改后的完整正文",
  "report": [
    {"issue_id": "A1", "level": "critical", "handled": true, "how": "简述这条怎么改的，例如：补足了环境描写，删掉了直陈情绪句"},
    {"issue_id": "A2", "level": "minor", "handled": false, "how": "无法在不破坏全文的情况下修复，说明原因"}
  ]
}
要求：report 里为**每一条**审计问题都给出一个条目，issue_id 必须与审计问题 id 完全一致；handled=true 表示已修复，false 表示无法修复；how 用一两句话说明具体改法。
